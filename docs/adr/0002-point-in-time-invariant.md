# ADR-0002 — Point-in-time данные как ключевой инвариант

- Статус: Accepted
- Дата: 2026-10-28
- Этап: 02 (решение из `docs/03`, реализация — Stage 12–14)

## Контекст

Бэктест, который видит отчётность, поданную после даты прогноза, выглядит отлично и ничего не доказывает (научный риск SR-02, SR-03).

## Решение

Факт доступен только с момента публикации (`filed_at` / `release_at`), а не с `period_end`. Каждое значение в contracts несёт `as_of` — knowledge cutoff с явным часовым поясом (`AwareDatetime`). Хранилище держит original, vintage и latest-версии значений и не мутирует историю.

## Как проверяется

Сейчас: contracts отклоняют `as_of` без часового пояса. Stage 12: adversarial fixtures с будущими датами подачи, leakage-тесты как blocking в CI.

## Последствия

Любая функция feature building принимает cutoff явно. Запросы без cutoff к историческим данным запрещены на уровне API (PRD FC-04).

## Отвергнутые альтернативы

Использовать последнюю версию данных и «помнить» про утечку: не проверяется и ломается при первой ошибке.
