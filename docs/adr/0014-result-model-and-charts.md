# ADR-0014 — Контракт результата с парными разностями и одна модель данных для всех видов

- Статус: Accepted
- Дата: 2026-10-28
- Этап: 06

## Контекст

Timeline Explorer и Universe Compare показывают одно и то же разными способами: график, KPI, таблицу, CSV, сводку для screen reader. Если каждый вид считает свои числа, они разойдутся (PRD FR-RE-07).

Для режимов change и percent нужна разность alternate − baseline. Разность квантилей не равна квантилю разности: p10 разности по путям — не «p10 alternate минус p10 baseline».

## Решение

1. **Contract `ScenarioResult`** (contracts 0.4.0). В нём лежат:
   - история (только поданное к cutoff);
   - квантили p10 / p50 / p90 по каждому сценарию;
   - парные разности по путям: в долларах и, где baseline всегда положителен, в доле baseline (FP-08);
   - распределение парной разности на горизонте;
   - waterfall на средних;
   - события решения;
   - manifest;
   - состояние failed.

   Правила contract:
   - квантили упорядочены;
   - шаги waterfall складываются точно;
   - demo ⇒ synthetic и не калибровано;
   - mock ⇒ demo;
   - failed ⇒ нет чисел;
   - история не позже cutoff.
2. **Waterfall строится на средних**, потому что средние складываются, а медианы нет. Это написано на самом графике.
3. **Модель графика** (`apps/web/src/results/series.ts`) — единственный источник для всех видов результата. KPI берут последнюю точку той же серии, таблица и CSV — те же точки, сводка — те же KPI. Тест сверяет, что KPI — это тот же объект, что последняя точка серии.
4. **Цвета серий** — ступени цветов docs/10 внутри lightness band тёмной темы. Палитра проверена валидатором dataviz по всем парам. У каждой серии ещё и свой штрих, легенда и подпись, так что цвет не единственный носитель.
5. **Честные оси** (FP-09). Absolute всегда включает 0, change и percent симметричны около 0.
6. **Mock-генератор** (`multiverse_contracts.mock_results`) детерминирован и проверяется на дрейф. Результаты с одним seed, компанией и cutoff имеют одинаковые baseline-пути. Их совместимость показывает Compare, несовместимые блокируются (FC-09).

## Как проверяется

- `uv run pytest packages/contracts`: фикстура не устарела, тот же seed даёт те же числа, нулевой эффект = baseline на каждом пути, у результатов с одним seed baseline совпадает, 9 видов сломанного результата отклоняются.
- vitest `results.test.ts`: KPI = точки графика, change берёт парные разности, оси, округление FP-02, CSV, совместимость.
- Playwright `results.spec.ts` на трёх ширинах.

## Последствия

Monte Carlo (Stage 22) заполняет тот же contract реальными путями, и страницы менять не нужно. Новый вид результата строится из модели графика, а не из сырых данных.

## Отвергнутые альтернативы

- **Считать change как разность полос.** Это неверно для квантилей и скрывает парность.
- **Хранить все пути в результате.** 500 путей × 5 метрик × 3 сценария тяжело для страницы. Пути понадобятся только для диагностики (Stage 22, `GET /simulations/{id}/paths`).
- **Библиотека графиков.** Нужны контроль над доступностью, честными осями и мобильной вёрсткой, а SVG здесь небольшой.
