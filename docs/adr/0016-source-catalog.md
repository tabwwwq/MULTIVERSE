# ADR-0016 — Каталог источников как contract: загрузки только по решению владельца, бесплатный доступ ≠ лицензия

- Статус: Accepted
- Дата: 2026-10-29
- Этап: 09

## Контекст

Phase B начинается с реальных источников: SEC EDGAR, FRED/ALFRED, ECB, World Bank, позже лицензированные market data (`docs/04`). У каждого свои правила: SEC требует declared User-Agent и не больше 10 запросов в секунду; FRED требует личный ключ, а серии третьих лиц — разрешения владельца; ECB разрешает reuse только без изменения статистики; World Bank даёт CC BY 4.0 с исключениями. Описания API устаревают. Ошибка в любом из этих пунктов — это блокировка доступа, утечка будущего или нарушение условий (`docs/12`).

## Решение

1. **Каталог — это contract** (contracts 0.6.0, `sources.py`), а не текстовый документ. `SourceCatalog` хранит источники, наборы данных со словарём полей, лицензии, rate limits, правила повторов и checksums, решение о загрузке, реестр рисков, приоритет секторов, рубрику, кандидатов и план загрузки. Содержимое — `source_catalog.py`, генератор пишет `catalog/sources.json` с проверкой drift; web-приложение читает тот же файл.
2. **Правила, которые проверяет contract:**
   - у источника есть техническая документация и terms или access policy;
   - все ссылки — HTTPS на официальных хостах этого источника;
   - категория доступа, аутентификация и статус ключа согласованы (public access → ключ не нужен; API key → ключ регистрирует владелец; licensed → контракт);
   - resale «разрешён» только при явной лицензии (open licence или reuse with conditions); бесплатный доступ сам по себе даёт «not granted»; лицензированные данные никогда не перепродаются;
   - выбранная скорость запросов положительна и не выше документированной;
   - у решения о загрузке есть дата ровно тогда, когда оно принято;
   - риски и шаги плана ссылаются на известные источники; кандидаты ранжированы по сумме баллов рубрики.
3. **Загрузки выключены.** `automatic_downloads` в каталоге — только `"disabled"`; у всех источников решение `awaiting_owner_decision`. В Stage 10 загрузчик обязан требовать одновременно `MULTIVERSE_ALLOW_NETWORK_DOWNLOADS=true`, `MULTIVERSE_SEC_USER_AGENT` с email и решение `approved` для источника.
4. **Факты о компаниях отделены от ожиданий.** В каталоге кандидатов только сверенные поля (CIK, SIC, конец финансового года, категория filer, тикеры); каждый балл рубрики помечен `verified` или `expected`, и ожидания проверяются на данных в Stage 10–11.
5. **Сырые данные не попадают в git.** Каталог хранит только метаданные и инструкции загрузки; байты источников — в `var/raw/`, с SHA-256, заголовками и версией terms.

## Последствия

- Изменение условий источника — это изменение contract с тестом, а не правка текста.
- Data Catalog в интерфейсе и будущий `GET /api/v1/sources` показывают одно и то же.
- Дата проверки документации видна у каждого источника; перед первой загрузкой её нужно обновить.
- Лицензированные market data описаны как потребность без поставщика: V2 работает без них (DCF без цены акции).
