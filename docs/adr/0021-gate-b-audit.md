# ADR-0021 — Gate B: аудит по usable examples, проверки со статусом blocked, сверка как данные

- Статус: Accepted
- Дата: 2026-10-30
- Этап: 14

## Контекст

Промпт 14 требует исчерпывающий аудит финансового датасета перед ML:

- data card и визуальный отчёт о покрытии;
- checklist из 15 рисков;
- фактические числа: компании с 8/12/20 кварталами, trainable examples по горизонтам, missingness, effective size, конфликты источников;
- решения об исключении компаний;
- доказательство отсутствия утечки;
- 10 ручных сверок с оригиналами SEC;
- dataset manifest с hash.

«Зелёные тесты или честный blocked report». Размер датасета нельзя мерить числом скачанных файлов.

Данные: sample SEC из 10 компаний (решение D-09), реальной макроэкономики нет (D-11, D-12 не приняты). В docs нет числового порога готовности датасета.

## Решение

1. **Модуль `multiverse_pipelines.audit`**, команда `run`. Читает только локальные данные (PIT warehouse, raw archive, macro stores, файл сверки). Пишет в `var/data/gate/`: `manifest.json`, `examples.csv`, `data-card.md`, `coverage.html`.
2. **Contract `GateCheck`** (contracts 0.11.0): статус `pass` / `warning` / `fail` / `blocked`, измерения и до 40 конкретных случаев. Проверка, которая не прошла, обязана показать, что нашла. `blocked` значит: данные пока не выдерживают следующий шаг, и проверка говорит, чего не хватает.
3. **Checklist промпта — 15 проверок** (`audit/checks.py`):
   - future revisions;
   - duplicated company-quarter;
   - concept drift;
   - survivor-only sample;
   - lost bankruptcies (8-K item 1.03 в индексе);
   - missingness;
   - revenue gaps;
   - negative / undefined ratios;
   - currency / FX;
   - outliers (robust z по log-изменениям);
   - unrealistic q/q jumps;
   - cumulative cash flow;
   - misidentified CAPEX;
   - reported vs calculated EBITDA;
   - source conflicts.

   Плюс четыре проверки gate: leakage proof, manual reconciliation, usable sample size, macro data.
4. **Размер — в usable examples.** Example — компания и forecast origin (конец календарного квартала), у которых:
   - последние H кварталов перед origin (лаги 1…H) имеют выручку в PIT panel на origin (vintage);
   - выручка квартала через h кварталов есть как первый выпуск (original) к data cutoff.

   Лаг 0 никогда не входит в историю: его отчёт ещё не опубликован. Числа даются для H = 8, 12, 20 и h = 1, 4, 8, 12, 20 (docs/06). Таблица examples хешируется; hash называет датасет (`gate-b-<дата>-<12 hex>`).
5. **Порог готовности (предложение, в docs его нет):** не меньше 30 компаний с 12+ кварталами выручки и не меньше 1 000 examples при H = 12, h = 4. Это минимальная cross-section, на которой можно отделить общий сигнал от особенностей отдельных компаний и честно разделить train / test по времени. Порог — константа в коде, её можно пересмотреть.
6. **Leakage proof исполняемый.** Warehouse пересобирается только из того, что было public на трёх cutoff, и snapshot сравнивается побайтно с полным archive. Так же сравниваются macro join (на синтетике). Отличие — `fail`.
7. **Ручная сверка — это данные.** 10 значений, прочитанных вручную со страниц filings на sec.gov, лежат в `data/reconciliation/stage-14-manual.json`: страница, строка, значение как показано, единица, ожидаемое производное. Gate сверяет их с warehouse на каждом запуске. Ручная работа не теряется, и регрессия нормализации ломает gate. Меньше 10 сверок — `blocked`, расхождение — `fail`.
8. **Решения об исключении — по метрикам.** Для датасета выручки компания включается при 12+ кварталах. Для каждой метрики перечислены компании с 12+ кварталами, остальные исключаются из экспериментов с этой метрикой (R&D — у 4 из 10, COGS — у 7). Deregistration ограничивает origins.
9. **Вердикт следует из проверок** (contract `GateManifest`): `blocked` ровно тогда, когда есть `fail` или `blocked`; при одних warnings — `passed_with_warnings`; вердикт без причин не принимается; view `latest` не допускается.

## Как проверяется

- `pipelines/tests/test_audit.py` — синтетический «спокойный» эмитент за семь лет:
  - examples: история только из public кварталов, цель — через h кварталов и выпущена к cutoff, hash не зависит от порядка;
  - чистые данные проходят проверки;
  - скачок выручки найден и назван;
  - сверка: 10 совпадений — `pass`, расхождение — `fail`, 9 — `blocked`;
  - размер и макро блокируют честно;
  - команда пишет blocked report с leakage proof, manifest и data card.
- `packages/contracts/python/tests/test_quality.py` — вердикт не может разойтись с проверками, проверка без находок не может не пройти, датасет назван своим hash.

## Последствия

- Gate B на sample честно `blocked`: 10 компаний, 447 examples при H = 12, h = 4, нет реальной макроэкономики. Механика данных (утечка, сверка, manifest) проходит.
- Снятие блокировки — решения владельца: D-10 (bulk-файлы SEC для полной вселенной), D-11 и D-12 (макроэкономика). После них gate запускается той же командой.
- Stage 15 (baselines) на sample возможен только как пилот, помеченный пилотом, по решению владельца.

## Отвергнутые альтернативы

- **Считать «большие данные» по числу файлов или строк.** 34 файла дают 70 934 интервала значений, но всего 447 examples при H = 12, h = 4. Промпт запрещает такой счёт.
- **Объявить Gate B пройденным, потому что тесты зелёные.** Тесты проверяют механику, а не достаточность данных. Промпт прямо допускает blocked report.
- **Хранить ручную сверку только в отчёте.** Тогда её нельзя перепроверить. JSON со ссылками на страницы делает её воспроизводимой.
- **Жёсткие пороги outliers и jumps как `fail`.** Кризис 2008–2009 и продажи бизнесов — реальные события, а не ошибки. Они видны как warning со списком.
