# ADR-0023 — Baselines прогноза: один датасет, закреплённый протокол, честное сравнение с persistence

- Статус: Accepted
- Дата: 2026-10-30
- Этап: 15

## Контекст

Промпт 15 требует:

- единый research protocol для пяти целей: revenue growth, operating и EBITDA margins, FCF margin, debt/EBITDA;
- baselines — persistence/seasonal naive, sector average, Ridge/ElasticNet, gradient boosting, эконометрическая панель;
- одинаковые снимки признаков, cutoff, цели и маски для всех моделей;
- нормализацию только на train;
- rolling origin и отдельный holdout фирм для cold start;
- корректное время выпуска цели;
- никаких придуманных accuracy.

Нейросети запрещены до Stage 16.

Данные — вселенная из 1000 компаний (ADR-0022), PIT warehouse (ADR-0019), реальное макро (ADR-0020). Слои модулей (ADR-0009) не дают `multiverse_forecast` импортировать `multiverse_pipelines`.

## Решение

1. **Датасет строят pipelines, модели — forecast.** `python -m multiverse_pipelines.forecastset build` пишет `var/data/forecast/<id>/dataset.csv` и `manifest.json` (`ForecastDatasetManifest`, contracts 0.13.0). Id — SHA-256 CSV. `multiverse_forecast` читает только эту папку и проверяет hash.
2. **Признаки — то, что было public на origin.**
   - Источник — panel Stage 12 (vintage, лаги 1–8; лаг 0 не используется никогда) через уже проверенный на утечку `build_panel`.
   - Макро — последнее доступное значение каждой серии на конец дня origin.
3. **Цели — первый выпуск с моментом выпуска.**
   - Значение квартала origin + h берётся в original view на data cutoff. Рядом хранится момент публикации: максимум из моментов составляющих.
   - Модель фолда Y учится только на строках, чья цель была опубликована до 1 января Y (конец 31 декабря по Eastern).
4. **Определения целей.**
   - Рост выручки симметричный: (a − b) / ((a + b) / 2), в пределах [−2, 2]. Обычное отношение a / b − 1 на крошечной базе даёт −918 900% у одной компании, и несколько почти нулевых выручек решают любую метрику.
   - Маржи — доля выручки, не определены при выручке ≤ 0.
   - Debt/EBITDA — долг на конец квартала к EBITDA за четыре квартала; не определён, если эта EBITDA ≤ 0.
   - Неопределённые значения считаются отдельно и не оцениваются. Отрицательный FCF и убытки остаются.
5. **Протокол закреплён файлом** `data/protocols/stage-15-baselines.json` (`ForecastProtocol`). Его SHA-256 входит в каждый отчёт. Протокол задаёт:
   - seed;
   - цели и горизонты 1/4/8/12/20;
   - validation 2016–2019 и test 2020–2026;
   - 20% фирм для cold start (по seeded hash CIK);
   - порог «существенной» выручки $10 млн;
   - winsor 1%;
   - 1000 bootstrap-выборок;
   - сетки гиперпараметров.
6. **Validation выбирает, test оценивает один раз.**
   - Настройка модели выбирается по MAE на validation (горизонты 1, 4, 8; цели опубликованы до начала test).
   - На test применяется только выбранная настройка, отдельно для training-фирм (test) и для невиданных фирм (cold start).
7. **Одни и те же строки для всех моделей.** Строка оценивается, если цель опубликована и определена и на origin есть persistence. Тогда у каждой модели есть сравнение с persistence на тех же строках.
8. **Две популяции.** Все строки, и фирмы с TTM-выручкой ≥ $10 млн на origin. Фильтр известен в момент прогноза и не зависит от исхода.
9. **Train-only предобработка в каждом фолде.** Winsor-границы, медианы, масштаб и winsorизация обучающей цели считаются на обучающих строках фолда. Оцениваемая цель не winsorизуется никогда.
10. **Эконометрическая панель** — pooled dynamic panel: OLS на четыре собственных лага цели, макро и эффекты дивизиона SIC. Фирменные эффекты не используются: они не применимы к cold start, а на коротких панелях смещают коэффициент лага (Nickell).
11. **Метрики и интервалы.**
    - MAE, RMSE, median AE, WAPE;
    - firm-weighted и revenue-weighted MAE;
    - `vs_naive` = MAE / MAE persistence − 1;
    - 95% интервалы — bootstrap по фирмам: строки одной фирмы коррелированы;
    - ошибки по дивизионам, крупнейшие ошибки, выводы «сколько моделей не лучше persistence».
12. **Зависимости.** numpy и scikit-learn — основные зависимости `multiverse-forecast`: CI ставит workspace без extras. LightGBM и PyTorch остаются extras.

## Последствия

- Любое число отчёта прослеживается: benchmark id = SHA-256 конфигураций и оценок; рядом SHA-256 датасета и протокола.
- Stage 16 сравнивается на тех же строках, фолдах и популяциях.
- **Протокол менялся после одного пробного прогона, это раскрыто.** Пробный прогон на урезанном протоколе (одна цель, два горизонта, одна точка сетки) показал MAE роста выручки около 11, то есть 1100%. После этого определение роста стало симметричным, а популяция с выручкой ≥ $10 млн была объявлена до полного прогона. Изменение вызвано масштабом ошибки, а не тем, какая модель выигрывает.

## Как проверяется

- `packages/forecast/tests/test_baselines.py` — синтетическая панель:
  - hash датасета проверяется;
  - naive читает только public-лаги;
  - предобработка учится только на train;
  - обучение не видит ни позже опубликованной цели, ни фирмы из holdout;
  - все модели оцениваются на одних строках;
  - отчёт воспроизводим по seed;
  - команда пишет три файла.
- `pipelines/tests/test_forecastset.py` — симметричный рост, лаги 1–8 без лага 0, цели с моментом выпуска и меткой undefined, макро только из доступного на origin, стабильный CSV.
- `packages/contracts/python/tests/test_forecasting.py` — vintage-датасет и имя по hash, порядок validation/test, имя бенчмарка по hash.
