# ADR-0025 — Вероятностная оценка: семь квантилей, conformal на watch-фирмах, решение на final-годах

- Статус: Accepted
- Дата: 2026-11-05
- Этап: 17

## Контекст

Промпт 17 требует проверить вероятностный прогноз отдельно от точечного: pinball или CRPS, покрытие p50/p80/p90, резкость, reliability curve, режимы времени, ошибки по фирмам, разреженные отчёты, OOD, ablations, проверку на запоминание фирм, нетронутый финальный test. Approved model ID — только при реальной проверке.

Что мешает сделать это напрямую:

- Сеть Stage 16 выдаёт три квантиля. По ним измеряется только интервал 80%.
- Test 2020–2026 уже показан в отчётах Stage 15 и 16. Данных новее среза 2026-10-28 нет. Настройки по test не выбирались, но совершенно нетронутого периода не существует.
- У baselines нет распределений, а сравнивать нужно на одних строках.
- Отчёт Stage 16 собирался только после всех тренировок, и его падение стоило повторного прогона.

## Решение

1. **Протокол** `data/protocols/stage-17-evaluation.json` (`EvaluationProtocol`, contracts 0.15.0) закреплён файлом до первой оценки; его SHA-256 входит в пакет.
2. **Модель.** Настройки GRU и TCN берутся из выбора Stage 16 на validation, заново не подбираются. Меняется только голова: семь уровней 0,05/0,1/0,25/0,5/0,75/0,9/0,95, медиана свободна, каждый внешний квантиль — на softplus дальше соседа. На тестовый год 5 seeds, прогноз — среднее их квантилей. Конфигурация с тремя уровнями даёт те же checkpoint, что на Stage 16 (проверено побайтно).
3. **Пространство оценки.** Все вероятностные меры считаются в обучающем пространстве цели: рост как есть, маржи через asinh(y / 0,1), долг через asinh(y). Квантили переживают монотонное преобразование, а маржа −30 000 перестаёт решать среднее по фирмам. Median AE считается и в единицах цели.
4. **Меры.** Pinball по семи уровням, WIS (конечное приближение CRPS), покрытие и ширина интервалов 50/80/90%, reliability по всем уровням. 95% интервалы — bootstrap по фирмам.
5. **Калибровка — conformalized quantile regression.**
   - Калибровочные строки фолда Y — фирмы watch set: десятая часть обучающих фирм, которые только останавливают обучение и в градиент не входят.
   - Берутся только метки, опубликованные до начала Y.
   - Отступ считается отдельно для пары (цель, горизонт) и каждого интервала, в пространстве цели. Интервал может как расшириться, так и сузиться.
   - Гарантия conformal предполагает перестановочность. Для временных рядов её нет, поэтому значение имеет только покрытие, измеренное на более поздних годах.
   - Early stopping видел эти строки, поэтому покрытие может быть слегка завышено в пользу модели.
6. **Baselines с распределением**, на том же разделении меток:
   - `persistence`, `elastic_net`, `gbm`: точечный прогноз Stage 15 плюс квантили его ошибок на watch-строках (один разброс на всех);
   - `gbm_quantile`: градиентный бустинг на pinball, по модели на уровень, с той же калибровкой. Это честный соперник: его разброс зависит от фирмы.
7. **Периоды.**
   - Development 2020–2023: выбор архитектуры и решение, применять ли калибровку.
   - Final 2024–2026: вердикт. Это годы, не использованные ни для какого выбора, но входившие в сводные таблицы test на Stage 15–16. Честное название — «не использованный для решений», а не «нетронутый».
   - Метки 2024–2026 есть только на коротких горизонтах, поэтому вердикт выносится на h = 1, 4, 8.
8. **Ablations** (3 seeds на фолд против полной модели с теми же seeds): без макро, без R&D, без долга, история 12 и 4 квартала, без последовательности, без static, без масок, другая глубина. Только для описания: ни одна настройка по ним не выбирается.
9. **Запоминание.** Pinball на обучающих строках против watch-фирм того же периода; на test — знакомые фирмы против cold start, каждая группа относительно persistence, с интервалом.
10. **Нестабильность.** Сеть прямая, рекурсивного rollout нет. Измеряется, как меняется прогноз одного квартала при приближении origin (h = 8 → 4, 4 → 1, 12 → 8, 20 → 12), и разброс между seeds.
11. **Правило одобрения** записано в протоколе и применяется к final-годам по каждой паре (цель, горизонт):
    - не меньше 300 строк;
    - покрытие 50/80/90% на знакомых фирмах в пределах ±5 п. п., на cold start в пределах ±10 п. п.;
    - pinball лучше persistence с интервалом ниже нуля;
    - pinball не хуже лучшего baseline;
    - median AE не хуже persistence.

    Пара без всех шести условий не одобряется. Решение об утверждении модели принимает владелец.
12. **Хранение.** Обучение пишет полосы в `var/data/forecast/evaluation/<protocol>/bands/`, по файлу на модель. Сохранённый вариант второй раз не обучается. Отчёт читает только эти файлы: его падение ничего не стоит.
13. **Model id** `model-<дата>-<hash>` — SHA-256 датасета, протокола, имени модели, факта калибровки и всех checkpoint.

## Результат

Пакет `eval-20261028-b365e4a12ddb`, модель `model-20261028-9ce4d4180aa9`, отчёт `docs/stages/17-probabilistic-validation.md`:

- на development выбрана GRU без калибровки: средний разрыв покрытия 0,026 против 0,051 с калибровкой;
- сырые квантили откалиброваны в пределах 2–4 п. п., кроме шока 2020 года;
- сеть бьёт полосу persistence на 13 парах из 15 в final, но квантильный бустинг в сумме не хуже сети: он сильнее на h = 1, сеть — на h = 4–8;
- правило одобрения прошли 3 пары из 15: operating margin h = 8, EBITDA margin h = 4 и 8;
- признаков запоминания нет; макро, R&D, маски и глубина на pinball не влияют.

## Последствия

- Оценка воспроизводится из файлов за минуты, без обучения.
- Модель можно одобрить только для части целей и горизонтов. Это ожидаемый исход.
- Точечные результаты Stage 16 остаются в силе: модель с семью уровнями — отдельная модель с собственными оценками.

## Как проверяется

`packages/forecast/tests/test_evaluation.py` (идёт в CI, PyTorch не нужен):

- pinball и WIS совпадают с определением, настоящее распределение покрывает заявленное;
- conformal чинит узкий интервал, сужает широкий, уровни не пересекаются, медиана не сдвигается;
- bootstrap чувствует малое число фирм;
- отступы применяются к своему году;
- выбор модели не зависит от final-лет (порча этих лет ничего не меняет);
- все полосы оцениваются на одних строках;
- одобрение требует всех условий;
- пакет назван по hash и сохраняет failures.

`packages/forecast/tests/test_neural.py` (где установлен PyTorch): семь уровней упорядочены, три сохраняют формулу Stage 16, каждая ablation убирает только свой вход, остановленный прогон продолжается и не трогает готовое.
