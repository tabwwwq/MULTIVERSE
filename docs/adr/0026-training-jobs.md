# ADR-0026 — Training jobs: очередь в SQLite, аренда с heartbeat, checkpoint со всем состоянием

- Статус: Accepted
- Дата: 2026-11-05
- Этап: 18

## Контекст

Промпт 18 требует долгие обучения вне HTTP-запроса: durable queue, идемпотентный submit, heartbeat, журнал без секретов, настоящий checkpoint, best и last, остановка в безопасной точке, pause и resume, отказ при несовместимой схеме, статусы в UI, retry, OOM, NaN, бюджеты, cleanup.

Ограничения проекта:

- API не обучает внутри запроса и не импортирует `multiverse_forecast` (ADR-0003, import-linter).
- Сервисы — соседи, они не импортируют друг друга.
- Один пользователь, одна локальная GPU. Облако запрещено настройкой `cloud_spend_limit_usd = 0`.
- На Stage 17 процессы CUDA завершались с кодом 127 при записанных файлах. Код выхода нельзя считать источником правды.

## Решение

1. **Новый пакет `multiverse_jobs`** на уровне доменных пакетов: очередь, оценка ресурсов, очистка журнала. Он ничего не обучает, поэтому API читает его, не касаясь моделей. Worker зависит от него и от `multiverse_forecast`.
2. **Хранилище — SQLite в режиме WAL** (`var/data/jobs/jobs.sqlite`), одно короткое соединение на вызов, запись через `BEGIN IMMEDIATE`. Для одной машины этого достаточно: брокер не нужен. Каждый переход — одна транзакция, разрешённые переходы перечислены таблицей.
3. **Идемпотентность.** `job_id` — hash ключа. Тот же ключ и запрос дают ту же задачу (200), другой запрос с тем же ключом отклоняется (409).
4. **Одобрение.** Задача ждёт в очереди, пока оценка не одобрена. Оценка опирается на измеренные скорости Stage 16–17 и называет это в тексте.
5. **Аренда.** Worker берёт задачу на `ttl` секунд, отдельный поток продлевает её. Истёкшая аренда значит, что worker умер: следующий продолжает с checkpoint, попытка считается. После `max_attempts` задача становится `failed`. Worker, потерявший аренду, больше не пишет.
6. **Состояния** — как в промпте, плюс `stop_requested`: остановка запрошена, но безопасная точка ещё не достигнута.
7. **Запросы стоп и пауза** хранятся в задаче. Worker проверяет их после эпохи, когда состояние уже на диске.
8. **Checkpoint** (`multiverse_forecast.resumable`):
   - содержит модель, optimizer, scheduler, состояния numpy, torch и CUDA RNG, счётчики цикла, нормализацию, контрольный список совместимости и commit кода;
   - публикуется атомарно: запись рядом, fsync, переименование, затем SHA-256;
   - `last.pt` пишется после каждой эпохи, `best.pt` — при улучшении;
   - читается с `weights_only=True`;
   - resume отказывает, если отличаются датасет, последовательности, фолд, признаки, нормализация, архитектура, размер, dropout, уровни квантилей или seed. Размер batch может уменьшиться после нехватки памяти.
9. **Цикл обучения** разбит на `begin`, `step`, `finished`; `train` — их обычная последовательность. Обучение Stage 16 от этого не меняется: контрольный checkpoint совпал по SHA-256.
10. **Реакции worker:**
    - отказ проверки или несовместимый checkpoint — `failed` сразу, с alert;
    - потери не число — alert и `failed`, без retry;
    - нехватка памяти устройства — alert, retry с половиной batch от checkpoint;
    - прочие ошибки — retry от checkpoint, пока есть попытки.
11. **Бюджеты** проверяются после каждой эпохи и считаются по всем попыткам вместе: resume не даёт нового лимита. Лимит времени обязателен. Платной задаче нужен лимит денег. Больше 4 часов — только с явным `overnight: true`.
12. **Никаких случайных ночных обучений.** `multiverse-worker run` завершается, когда очередь пуста. Ожидание новых задач — только с `--watch`. Автозапуска нет.
13. **Принудительная остановка** — `multiverse-worker kill <job> --yes`: без `--yes` команда только предупреждает, что текущая эпоха потеряется.
14. **Журнал без секретов.** Строки проходят `redact` перед записью: ключи, токены, Bearer, почта, длинные hash.
15. **Прогресс** — эпохи к максимуму, 0–100%. Ранняя остановка переводит его сразу в 100%. Экран `/models` читает состояние раз в две секунды и передаёт запросы; браузер можно закрыть.
16. **Источник правды — база задач**, а не код выхода процесса.

## Последствия

- Обучение переживает закрытие браузера, смерть worker и перезапуск.
- Остановленная и возобновлённая задача даёт те же веса, что и непрерывная.
- SQLite ограничивает систему одной машиной. Для нескольких машин понадобится другой брокер; контракт и переходы останутся.
- API без аутентификации и слушает только 127.0.0.1. Доступ и роли — Stage 24.
