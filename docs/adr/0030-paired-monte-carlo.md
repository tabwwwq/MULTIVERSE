# ADR-0030 — Парный Monte Carlo: блочный бутстрэп истории, движок на каждом пути, условные вероятности

- Статус: Accepted
- Дата: 2026-11-06
- Этап: 22

## Контекст

Промпт 22 требует стохастическую симуляцию вокруг одобренного прогнозного слоя и финансового движка: общие внешние шоки у пары, коррелированные макро- и секторные шоки, временная зависимость, восстановление после недопустимых путей, детерминированный seed, диагностика сходимости, манифест, асинхронный API с бюджетом и отменой. Если калибровки нет, вероятности помечаются как условные.

Калибровки нет. Модель Stage 17 подписана только для исследования и только на 3 парах из 15. Рост выручки не подписан. В хранилище нет PP&E, goodwill, оборотного капитала и процентов.

## Решение

1. **Новый пакет `multiverse_simulation`** над доменными пакетами. API его не импортирует: контракт import-linter и тест.
2. **Шоки — строки истории.** Одна строка — один календарный квартал: макро, сектор, фирма вместе. Stationary block bootstrap (Politis, Romano) по этим строкам сохраняет связи между столбцами и во времени без модели ковариации. Столбцы центрированы, отклонения роста и маржи затухают по AR(1) с коэффициентом дивизиона.
3. **Каждый путь идёт через движок Stage 21** на `Decimal`. Для пары это две проводки одного baseline. Реконсиляция проходит внутри `project` для каждого пути.
4. **Один seed на путь.** Генератор ключуется run seed, номером пути, потоком и попыткой. Поток 0 внешний и общий, потоки решения отдельные, у каждого параметра свой. Следствия: решение не сдвигает шоки, размер батча и стоп с резюме не меняют числа, первые n путей длинного прогона и есть прогон на n.
5. **Центральный путь прозрачен и честен про источник.** Маржа EBITDA: медиана подписанной модели на 4 и 8 кварталах, между ними и после неё прямые линии. Рост: прозрачное правило, потому что модель для него не подписана.
6. **Недопустимый путь.** Отказ движка как невозможная настройка: новая попытка на следующем потоке, счётчик по коду. После всех попыток путь брошен, а не выдуман. Несошедшийся путь останавливает прогон: это ошибка, а не неудачная выборка.
7. **Вероятность сделки — исход пути.** Draw в потоке решения, а не масштаб проводок.
8. **Любой прогон идёт через очередь,** даже маленький. Запрос получает `kind`, старые строки читаются как обучение. Батч — безопасная точка, как эпоха: сюда приходят бюджет, стоп и пауза, здесь кадр уходит на диск.
9. **Контракт не примет откалиброванный отчёт.** `validation` и `probability_label` — литералы, `calibrated=True` отвергается. Режим результата `empirical_forecast`, причинный статус `assumption_based`.
10. **Кейс говорит, откуда каждое число.** `SimulationCase.inputs`: observed, implied, assumed, model. Экран показывает счёт и таблицу.
11. **Две даты.** `as_of` — момент знания, `balance_date` — последний отчётный квартал. Первый квартал пути — ещё не опубликованный.
12. **Цель покупки движется вместе с компанией** на пути (`target_follows_baseline`). Иначе парная разница не зависит от внешних шоков, а плоская цель противоречит растущему terminal value.

## Альтернативы

- **Параметрические шоки, Student-t, копула, смесь режимов.** `docs/08` называет их кандидатами после диагностики. Бутстрэп не требует допущения о форме. Цена — хвост не шире истории.
- **Выборка из квантилей сети.** Модель не подписана для большинства пар, а маргинальные квантили не задают совместный путь.
- **Векторизованный движок на float.** В сотни раз быстрее, но это второй финансовый движок и потеря тождеств на каждом пути. Сейчас 10 000 пар считаются примерно за минуту, поэтому не нужно.
- **Отдельная очередь для симуляций.** Дублировала бы аренду, heartbeat и бюджеты Stage 18.
- **Синхронный путь для маленьких прогонов.** Нарушил бы ADR-0003.

## Последствия

- Ни один прогон не покажет кризис, непохожий на кварталы истории, сколько бы путей ни было.
- WACC постоянен на всех путях, поэтому разброс EV идёт только от потоков.
- Stage 23 получает `SimulationReport` и кейс с отдельными параметрами стоимости капитала.
- Прогнозы модели попали в приложение, только в исследовательском кейсе и только на подписанных парах. Экран `/models` говорит об этом.
