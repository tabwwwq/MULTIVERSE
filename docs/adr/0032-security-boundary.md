# ADR-0032 — Граница API: локальный режим и токены, владелец объекта, лимиты в очереди

- Статус: Accepted
- Дата: 2026-11-06
- Этап: 24

## Контекст

Промпт 24 требует проверить auth, владение объектами, throttling, стоимость вычислений и секреты. Проверка живыми запросами показала: API на `127.0.0.1` не спрашивал, кто обращается, принимал задания с чужого сайта и одобрял их под любым именем. Лимит облачных расходов лежал в настройках и нигде не применялся.

Аккаунтов в продукте нет (D-07), публикации нет (OQ-07), а веб-страницы обращаются к локальному API напрямую. Docs/12 называет OIDC, но вход в браузере появится только с аккаунтами V4.

## Решение

1. **Два режима.** `local` доверяет только своей машине: принципал один, `owner` с ролью `admin`. Настройки запрещают этот режим вне loopback и в production. `token` требует Bearer-токен на каждый защищённый маршрут.
2. **`Guard` снаружи всего.** Он проверяет `Host`, для записи — `Origin` и `Sec-Fetch-Site`, тип и размер тела, и ставит заголовки ответа. Защита работает в обоих режимах, потому что в браузере владельца открыты чужие сайты.
3. **Токены.** 256 случайных бит, в настройках только SHA-256, срок обязателен и не больше 90 дней. Сессий и cookie нет, поэтому CSRF-токен не нужен.
4. **Роли.** `viewer` читает своё, `operator` ещё и запускает, `admin` одобряет и видит всё. Одобрение — единственное решение о деньгах, поэтому оператору оно недоступно.
5. **Владелец объекта — тот, кто подал задание.** Имя в теле должно совпасть с принципалом. Чужой объект отвечает 404, как несуществующий. Ключ идемпотентности привязан к владельцу.
6. **Лимиты в очереди, а не в API.** `JobStore` проверяет расходы, активные задания и секунды за сутки при подаче. Расходы проверяются ещё при одобрении и когда воркер берёт задание. Поэтому ни один путь в очередь их не обходит.
7. **Расход считается по максимуму.** Незавершённое платное задание резервирует весь свой лимит. Секунды считаются по `max_runtime_seconds`, а не по оценке.
8. **Аудит каждого защищённого чтения и действия.** Кто, что, какой объект, исход. Ни IP, ни токена: это минимизация данных.
9. **Запрет по лицензии живёт в каталоге.** `DataSource.blocks` хранит открытые блоки, `blocked_for_training` читает их. Снять блок можно только решением, записанным в каталоге, а не настройкой.

## Альтернативы

- **OIDC сейчас.** Нужен внешний провайдер и хостинг, то есть публикация, которой нет. Отложено до аккаунтов V4.
- **Токен и в локальном режиме.** Браузеру пришлось бы хранить секрет. Защиты он не прибавил бы: локальная программа и так читает `var/`.
- **Только `TrustedHostMiddleware` и CORS.** CORS не блокирует простые запросы: сервер их выполняет, браузер лишь прячет ответ. Живой запрос `text/plain` это подтвердил.
- **Лимиты в маршрутах.** Воркер и CLI обошли бы их.
- **Nonce в CSP.** Каждая страница стала бы динамической. Статическая сборка важнее, а риск закрыт отсутствием HTML-приёмников.
- **Подписанные ссылки на отчёты.** Отчёты читаются только через проверенный маршрут, хранилища со ссылками нет. Писать код без потребителя незачем. Правило для будущей ссылки записано в реестре.

## Последствия

- Веб-страницы работают только с `local` API. Публичный сайт потребует входа в браузере и TLS.
- Отчёт Stage 22 и его job id не меняются, но новые job id считаются иначе: ключ теперь включает владельца. Старые задания остаются читаемыми.
- Тело `approve` больше не содержит `by`: контракт клиента изменился.
- `protocol_path` принимает только `data/protocols/*.json`.
- Лимит ставки считается в памяти: рестарт его обнуляет.
- Новое обучение на датасете с сериями FRED отказывает, пока владелец не решит LIC-001.
