# ADR-0034 — Report Studio: отчёт из одного прогона, утверждения с указателями, повтор байт в байт

- Статус: Accepted
- Дата: 2026-11-07
- Этап: 25

## Контекст

Промпт 25 требует отчёт в Markdown, CSV и PDF с манифестом воспроизводимости. Отчёт должен пережить смену версии модели и данных, его утверждения должны проверяться, и синтетический результат не должен выдавать себя за рыночную правду. Приёмка: точный повтор одного отчёта по манифесту и разрешимость всех ссылок на источники.

До этого этапа у прогона был `SimulationReport` (Stage 22) с манифестом, а у блокнота — Markdown-отчёты вымышленных сценариев (Stage 07). Документа для чтения у реального прогона не было.

## Решение

1. **Документ строится только из прогона, кейса и решения.** Часов и машины в нём нет: время прогона и его длительность в документ не попадают. Одинаковые входы дают одинаковые байты.
2. **Идентичность наследует идентичность прогона:** `rep-<cutoff>-<sha12(report_id | generator_version)>`. `report_id` уже хэширует кейс (с датасетом и моделью), решение, настройки и версии движков. Новая модель или новые данные дают новый отчёт, старый остаётся прежним и повторяемым.
3. **Каждое число текста — утверждение** с JSON-указателем в `{report, case, decision}` и ссылками на источники. Генератор проверяет указатель при сборке, тест сравнивает значения после неё.
4. **Источники типизированы:** подача SEC (URL EDGAR по CIK из `case_id`), источник каталога, датасет, модель, метод (файл репозитория), прогон. Тест проверяет, что каждая ссылка разрешается.
5. **Десять разделов промпта 25 обязательны и идут по порядку.** Контракт отказывает документу без них, синтетическому документу без метки и заголовка «Synthetic» и реальному документу с синтетической меткой.
6. **Форматы.** Markdown для чтения. CSV в полных единицах, по одной статистике в строке. JSON-документ для экрана. Манифест с решением, настройками, хэшами кейса и трёх файлов. PDF — печать страницы `/reports` с печатными стилями: браузер сохраняет её в PDF без отдельного движка.
7. **Отчёт пишет воркер** вместе с `report.json`. API отдаёт файлы как есть, только владельцу прогона: чужой и несуществующий прогон отвечают одинаково 404. Прогоны до Stage 25 дописывает `multiverse-worker reports`.
8. **Повтор:** `python -m multiverse_simulation replay --manifest … --case …` запускает прогон заново, включая варианты чувствительности, и сравнивает все три файла байт в байт.

## Альтернативы

- **PDF на сервере** (reportlab, headless-браузер). Ещё одна зависимость и второй рендер того же документа. Отложено до публикации.
- **Текст, написанный моделью.** Числа в нём нельзя проверить указателем. Отвергнуто.
- **Отчёт собирает API.** Нарушило бы ADR-0003: API не считает. Отвергнуто.

## Последствия

- Отчёт без воркера не появится. Сайт без движка показывает подсказку `npm run app`.
- Повтор реального кейса требует кейса из `var/`, поэтому CI повторяет синтетический кейс, а реальный повторяется на машине, где кейс построен.
- Смена текста генератора меняет `generator_version` и тем самым идентичность. Старые манифесты повторяются старым генератором из истории git.
