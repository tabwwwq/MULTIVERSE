# Резервные копии и восстановление

## Что копируется

| Что | Копия | Почему |
|---|---|---|
| Очередь и аудит `var/data/jobs/jobs.sqlite` | ✅ | Единственное место, где они есть |
| Папки заданий и симуляций | ✅ | Чекпоинты и отчёты не пересобрать без вычислений |
| `var/raw` (4,6 ГБ) | ❌ | Неизменяемый архив с SHA-256, скачивается заново там, где условия это разрешают |
| Витрина, `var/data/forecast` и прочее | ❌ | Собирается из архива кодом из git |
| `.env` | ❌, никогда | В копии не должно быть секретов. Ключ FRED хранить отдельно |

## Команды

Создать копию. Папка должна быть новой, копия не заменяет другую:

```bash
uv run multiverse-worker backup var/backups/2026-11-06
```

Проверить копию по её манифесту:

```bash
uv run multiverse-worker verify var/backups/2026-11-06
```

Восстановить. Папка данных не должна содержать очереди, существующие данные не перезаписываются:

```bash
uv run multiverse-worker restore var/backups/2026-11-06 var/data-restored
```

После восстановления перенести папку на место `var/data` или указать её в `MULTIVERSE_DATA_DIR`.

## Как это устроено

- SQLite копируется через собственный backup API, поэтому очередь можно копировать во время работы.
- Манифест перечисляет каждый файл с SHA-256. Проверка падает на изменённом, пропавшем и добавленном файле.
- Восстановление сначала проверяет всю копию. Сломанная копия не трогает папку данных.

## Проверка восстановления

Выполнена 2026-11-06 на настоящих данных `var/data`.

| Шаг | Результат |
|---|---|
| Копия | 33 файла, 8 заданий, 7,7 МБ, 2,2 с |
| Проверка манифеста | Пройдена |
| Восстановление в пустую папку | 1,8 с |
| Сравнение таблиц `jobs`, `logs`, `metrics`, `alerts`, `audit` | Совпали по числу строк и хэшу содержимого: 8, 119, 62, 1, 0 |

Цели: **RPO** — время с последней копии, копии делаются вручную. **RTO** — минуты для очереди и отчётов.

## Что не закрыто

- **Копия лежит на том же диске.** От поломки диска она не защищает. Папку нужно копировать на внешний носитель. Выбор места — решение владельца.
- **Копия не зашифрована.** Секретов в ней нет, но есть имена и журнал. Внешний носитель нужно шифровать, например BitLocker.
- **Расписания нет.** Копии делаются вручную. Рекомендация: после каждого значимого прогона и раз в неделю при активной работе.
- **Срок хранения:** держать последние 7 копий, старые удалять вручную.
