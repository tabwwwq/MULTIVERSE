# План реагирования на инциденты

Роль на всех шагах одна: владелец проекта. Если появится команда, роли разделяются.

## Общий порядок

1. **Остановить утечку.** Отозвать ключ, остановить процесс, закрыть доступ.
2. **Сохранить следы.** Сделать копию `var/data/jobs/jobs.sqlite` до любых изменений.
3. **Оценить.** Что затронуто, с какого момента, есть ли риск для людей.
4. **Исправить.** Причину, а не только симптом, с тестом на этот случай.
5. **Записать.** Строка в [реестре проблем](issue-register.md) и в журнале дня.

## Сценарии

### Секрет попал в git

Считать секрет раскрытым с момента пуша. Удаление коммита его не вернёт: зеркала и кэши уже могли его забрать.

1. Сначала отозвать ключ у поставщика. Для FRED — в аккаунте владельца на сайте FRED.
2. Выпустить новый и записать только в `.env`.
3. Проверить `var/` и логи на старое значение.
4. Историю не переписывать без отдельного решения владельца. Правило проекта запрещает force-push.

### Украден токен API

1. Удалить запись из `MULTIVERSE_API_PRINCIPALS` и перезапустить API.
2. Прочитать аудит за период:

```bash
curl -H "Authorization: Bearer <токен администратора>" "http://127.0.0.1:8000/api/v1/audit?limit=1000"
```

3. Остановить чужие задания и выпустить новый токен:

```bash
uv run python -m multiverse_api.tokens --name <имя> --role operator --days 30
```

### Неожиданная работа воркера или расход

1. Посмотреть очередь:

```bash
uv run multiverse-worker status
```

2. Остановить задание с безопасной точкой через экран `/models` или `POST /jobs/{id}/stop`.
3. Если процесс не отвечает, завершить его без безопасной точки:

```bash
uv run multiverse-worker kill <job id> --yes
```

4. Лимит расходов равен нулю. Платное задание при таком лимите не примет ни очередь, ни воркер. Если оно появилось, это ошибка кода: завести проблему.

### Утечка персональных данных

1. Определить, чьи данные, сколько, насколько чувствительны.
2. Если есть риск для людей, уведомить надзорный орган **в течение 72 часов** с момента, когда стало известно (GDPR ст. 33).
3. При высоком риске уведомить самих людей (ст. 34).
4. Записать инцидент, даже если уведомлять не нужно (ст. 33 п. 5).

Сейчас аккаунтов нет, поэтому этот сценарий относится в основном к будущей публичной версии.

### Подменён файл модели или данных

1. Не загружать файл. Чекпоинт с неверным SHA-256 загрузка отвергнет сама.
2. Сверить `var/raw` с его индексом.
3. Восстановить из копии по [инструкции](backup-restore.md) или пересобрать.

### Правообладатель или поставщик данных прислал требование

1. Прекратить спорное использование. Новую загрузку и обучение на этом источнике заблокировать в каталоге.
2. Показать требование владельцу, отвечает только владелец.
3. Обновить [реестр лицензий](license-inventory.md).

### Уязвимость в зависимости

1. Проверить, доходит ли уязвимый код до работающего приложения.
2. Обновить lock-файл, прогнать `npm run check`.
3. Job `Dependency audit` в CI ловит новые записи при каждом пуше.
