## 1. Подтверждение понимания

MULTIVERSE — исследовательская платформа, а не «нейросеть, которая знает альтернативное прошлое». Пользователь выбирает компанию, историческую дату (as-of) и финансово определённую интервенцию. Система сравнивает baseline и intervention scenarios по revenue, EBITDA, FCF, net debt, enterprise value и вероятностному риску. Каждый результат показывает происхождение данных, допущения, тип неопределённости и уровень вывода.

Принятые правила работы:

1. **Иерархия:** последнее сообщение пользователя и текущий этап → `17_ACCEPTANCE_MATRIX` → docs 01–18 → официальная документация источников → собственные решения через ADR.
2. **Один этап за раз.** Каждый этап заканчивается отчётом Done / Files / Tests / Measured results / Known limitations / Decisions / Next prompt и остановкой.
3. **Без фикций.** Нет выдуманных accuracy, кривых обучения, объёмов данных, ссылок и выполненной работы. Synthetic data всегда видимо помечены.
4. **Без самовольных расходов.** Облачные GPU, покупки лицензий, публикация и мутации внешнего storage — только после отдельного разрешения пользователя.
5. **Модули, а не монолит.** Typed contracts, тесты, schema, migrations, маленькие fixtures. Явно отмечается, что создано, а что только спроектировано.

**Отклонение от мастер-промпта.** Мастер-промпт требует после подтверждения ждать prompt 01. Пользователь в чате 2026-10-28 явно попросил сразу начать первый промпт. Поэтому Stage 01 выполнен в той же сессии. После Stage 01 работа остановлена до команды на Stage 02.

## 2. Ключевые научные риски

| # | Риск | Почему опасен | Чем закрываем | Этапы |
|---|---|---|---|---|
| SR-01 | **Selection и confounding.** Решения (R&D, M&A, layoffs) принимаются из-за скрытых ожиданий U_t и состояния S_t | Разница «после решения» ≠ причинный эффект. Модель выучит корреляцию, а UI её продаст как причину | Уровни descriptive / predictive / causal в каждом результате. DAG, overlap, pre-trends, placebo, sensitivity к hidden confounding. Causal label никогда не включается автоматически | 05, 19, 20 |
| SR-02 | **Look-ahead leakage.** Использование значений по `period_end`, а не по `filed_at` | Backtest выглядит отлично, а в реальности модель знала будущее | PIT-инвариант: факт доступен только с `filed_at` / `release_at`. Adversarial fixtures с датами в будущем. Тесты, блокирующие утечку | 12, 13, 14 |
| SR-03 | **Restatement leakage.** Поздние исправления отчётности подменяют исходные значения | Прошлое «улучшается» знанием будущего | Хранение original / vintage / latest. Прогноз на дату t видит только версии, поданные до t | 11, 12 |
| SR-04 | **Ошибки квартализации XBRL.** YTD-суммы, Q4 = FY − 9M, 53-недельные годы, смена concepts | Неверные кварталы ломают все targets и features | Явные правила по concept / duration / form, unit tests на Q1–Q4 и 53-week, ручная сверка с SEC | 11, 14 |
| SR-05 | **Survivorship bias.** Выбывшие и обанкротившиеся компании пропадают из выборки | Модель недооценивает downside, распределения слишком оптимистичны | Включать delisted фирмы, банкротство как конкурирующий исход, coverage report по выбывшим | 09, 14, 15 |
| SR-06 | **Маленькая эффективная выборка.** Мало фирм с ≥ 20 кварталами и стабильно размеченным R&D | Нейросеть переобучится или запомнит компании, baseline победит | Сначала coverage report и baselines. Нет firm-ID lookup. Cold-start holdout по фирмам. Отрицательный результат допустим | 14, 15, 16, 17 |
| SR-07 | **Слабая идентифицируемость экзотических counterfactuals** («Apple без iPhone») | Нет наблюдаемого ground truth, любая цифра — экстраполяция | Режим `FICTIONAL EXPLORATORY`, широкая uncertainty, предупреждение о structural extrapolation | 05, 22 |
| SR-08 | **Forecast accuracy ≠ policy effect accuracy** | Хороший MAE прогноза не подтверждает эффект интервенции | Раздельная оценка: forecasting benchmark и causal evaluation. Отдельные метки в UI и отчётах | 15, 17, 20 |
| SR-09 | **Некалиброванные интервалы.** Квантили модели выдаются за вероятность исхода | Ложная точность, неверные решения пользователя | Подпись «conditional model quantiles», статус калибровки, эмпирическое coverage 50 / 80 / 90% до снятия флага | 17, 22 |
| SR-10 | **Смешение финансовых величин.** EV / equity value / price, FCFF / FCFE / CFO − CAPEX, EBITDA без определения | Неправильная оценка, потеря доверия финансовых ревьюеров | Словарь метрик (`docs/product/07-metric-definitions.md`), API-поле `kind` и `unit`, property tests на bridge | 01, 21, 23 |
| SR-11 | **Нарушение финансовых тождеств в Monte Carlo.** Независимые шоки KPI, проверка только медианы | Пути, где FCF не следует из P&L, а долг не сходится | Шоки через drivers, коррелированные шоки, reconciliation на каждом пути | 21, 22 |
| SR-12 | **Macro vintage leakage.** Текущие ревизии FRED вместо ALFRED-vintages, годовые данные World Bank до релиза | Скрытая утечка будущего через макро-признаки | as-of join по времени публикации, тесты на запрет будущих ревизий | 13 |
| SR-13 | **Неоднозначное определение treatment.** «+40% R&D»: от бюджета или в p.p. выручки? Announced ≠ executed | Несопоставимые события, неверные labels | Ontology со строгими units, разделение announced / effective / completed, evidence с цитатой | 05, 19 |
| SR-14 | **Неконтролируемые вычисления.** Долгое обучение «на всякий случай» | Расходы без улучшения качества | Dry-run, spend cap, early stopping, обязательное разрешение пользователя | 16, 18 |
