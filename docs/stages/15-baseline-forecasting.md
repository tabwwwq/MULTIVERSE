## 1. Scope

Единый research protocol для пяти целей и семь baselines на одних и тех же строках:

- **цели** — revenue growth, operating margin, EBITDA margin, FCF margin, debt/EBITDA;
- **baselines** — persistence, seasonal naive, sector average, pooled dynamic panel, Ridge, ElasticNet, gradient boosting.

Нейросетей нет: они разрешены только на Stage 16 по отдельной команде. Новых загрузок нет.

## 3. Отчёт этапа

### Done

- **Датасет** (`python -m multiverse_pipelines.forecastset build --universe data/universe/sec-1000-20261030.json`) пишет `var/data/forecast/<id>/` (не в git).
  - Одна строка — компания и forecast origin (конец календарного квартала 2010Q1–2026Q3).
  - Признаки берутся из PIT panel Stage 12 на origin (vintage, лаги 1–8, лаг 0 никогда) через `build_panel`, уже проверенный leakage proof:
    - рост выручки за 4 лага;
    - логарифм TTM-выручки;
    - операционная, EBITDA- и FCF-маржа за 4 лага;
    - TTM-интенсивности capex, R&D, денег;
    - debt/EBITDA, чистый долг к выручке;
    - глубина истории, квартал origin;
    - 10 макро-признаков: последнее значение, доступное на конец дня origin.
  - Цели квартала origin + h берутся в original view на data cutoff, с моментом выпуска (максимум из моментов составляющих).
  - Id датасета — SHA-256 CSV.
- **Протокол** (ADR-0023) закреплён файлом, его SHA-256 входит в отчёт:
  - 20% фирм — cold start по seeded hash CIK;
  - rolling origin с ежегодным переобучением: модель года Y учится только на целях, опубликованных до 1 января Y;
  - validation 2016–2019 выбирает настройку по MAE (горизонты 1, 4, 8);
  - test 2020–2026 оценивается один раз выбранными настройками.
- **Модели** (`multiverse_forecast.models`):
  - persistence и seasonal naive (последний public-квартал той же календарной позиции);
  - sector average (среднее дивизиона SIC за два года обучающих origins);
  - panel_ar — pooled OLS на 4 собственных лага, макро и эффекты дивизиона, без фирменных эффектов;
  - Ridge и ElasticNet (стандартизация, медианы и маски по train);
  - HistGradientBoosting (пропуски нативно).

  Winsor 1% признаков и обучающей цели — по train фолда. Оцениваемая цель не трогается.
- **Одни и те же строки:** строка оценивается, если цель опубликована и определена и на origin есть persistence. Внутри (цель, горизонт, split, популяция) у всех моделей одинаковое число примеров — это проверяется тестом.
- **Оценка** (`scoring.py`):
  - MAE, RMSE, median AE, WAPE;
  - firm-weighted и revenue-weighted MAE;
  - `vs_naive` с 95% интервалом — bootstrap по фирмам, 1000 выборок;
  - MAE по дивизионам SIC (h = 1, 4);
  - крупнейшие ошибки лучшей модели;
  - findings: сколько моделей лучше persistence и что говорит median AE.
- **Две популяции:** все строки, и фирмы с TTM-выручкой ≥ $10 млн на origin (известно в момент прогноза).
- **Отчёт:** `var/data/forecast/<benchmark id>/report.json` (`BenchmarkReport`), `report.md`, `report.html`. Скриншоты — `docs/stages/15-screens/`.
- **Зависимости:** numpy 2.5.4 и scikit-learn 1.9.1 (с scipy 1.18.1) стали основными зависимостями `multiverse-forecast`; LightGBM остаётся extra.

- **На всех строках** learned-модели снижают MAE маржей на 20–50% относительно persistence. Выигрыш возникает только на крайних случаях: квартальные маржи фирм с почти нулевой выручкой (операционная маржа до −30 900, то есть −3 090 000%). Интервалы широкие: при h = 4 ни одна модель не лучше persistence с интервалом ниже нуля (0 из 6 по операционной и EBITDA-марже).
- **Для типичной фирмы** persistence лучше всех. Median AE операционной маржи при h = 4: persistence 0,088, ridge 1,63, sector average 4,29. Squared loss на целях с тяжёлыми хвостами сдвигает прогноз нормальных фирм.
- **У фирм с выручкой ≥ $10 млн** ни одна модель не лучше persistence с 95% интервалом ниже нуля ни по одной марже ни на одном горизонте. Точечные улучшения (FCF: h = 1 −15,4%, h = 8 −8,0%, h = 20 −6,6%; EBITDA: h = 8 −3,7%) лежат внутри интервала.
- **Debt/EBITDA:** по MAE learned-модели лучше на 45%, по median AE хуже (1,19 против 0,66). Revenue-weighted MAE близка (2,19 против 2,48).

Выводы промпта: «если 2/4 моделей не улучшают naive — зафиксируй». Фиксирую.
- По операционной и EBITDA-марже у фирм с существенной выручкой **6 из 6** моделей хуже persistence по точечной MAE на h = 1, 4, 12 и 20.
- По MAE на всех строках «лучше» в основном за счёт сжатия экстремальных значений.

Полная таблица по целям, горизонтам, популяциям, дивизионам и весам — в `report.md` бенчмарка.

**Выбранные на validation настройки:**
- **Ridge:** alpha = 1000 для всех пяти целей — граница сетки.
- **ElasticNet:** alpha 0,01, l1_ratio 0,5 — тоже граница.
- **GBM:** чаще самая регуляризованная настройка (max_depth 3, learning_rate 0,1, 150 итераций, min_samples_leaf 200); для FCF margin — max_depth 3, learning_rate 0,05, 300 итераций, min_samples_leaf 50.

Validation просит больше регуляризации, чем даёт сетка.

**Крупнейшие ошибки (test, h = 4, лучшая модель):**
- **Рост выручки:** −2 (выручка исчезла: фирма перестала продавать или отчитываться) при прогнозе +0,4…+0,6 у пяти случаев 2020–2021 годов. События ухода из бизнеса остаются в оценке.
- **Операционная маржа:** −30 910 при прогнозе −49,6 (CIK 0001437283, origin 2021-12-31).

### Known limitations

- **Квартальные маржи и debt/EBITDA имеют тяжёлые хвосты.** MAE на всех строках меряет в основном несколько фирм с почти нулевой выручкой или EBITDA. Смотреть нужно на median AE, revenue-weighted MAE и популяцию ≥ $10 млн. Цели на TTM-основе и устойчивые функции потерь — гипотезы для следующей версии протокола: их выбор должен идти по validation, не по этому test.
- **Протокол менялся один раз после пробного прогона** (ADR-0023). Пробный прогон на урезанном протоколе показал MAE роста ≈ 11. Определение роста стало симметричным, и популяция ≥ $10 млн добавлена до полного прогона. Модели после полного прогона не менялись.
- **Сетки упираются в границу** (Ridge alpha = 1000, ElasticNet alpha = 0,01). Validation хочет больше регуляризации; расширение сетки — тоже следующая версия протокола.
- **ElasticNet при alpha 1e-4** на маржах местами не сходится за 5000 итераций (ConvergenceWarning). Эта настройка на validation не выбрана ни разу.
- **Мало примеров на длинных горизонтах:** test h = 20 — 1 602 примера и 285 фирм; на validation h = 12 и 20 не оцениваются, потому что цели опубликованы после начала test.
- **Cold start — 20% фирм** (124–130 фирм на h = 1–4). Интервалы шире, чем у test.
- **Survivorship и покрытие наследуются от вселенной** (ADR-0022): нет компаний, умерших в первые три года XBRL, и нет иностранных эмитентов.
- **World Bank** в признаки не входит: один текущий snapshot, на исторических origin его нет.
- **Сравнения со Stage 16** допустимы только на этом же датасете и протоколе (те же SHA-256).

### Decisions

- Датасет строят pipelines, модели читают только папку датасета (ADR-0009, ADR-0023).
- Рост выручки симметричный; маржи и debt/EBITDA — классические, с меткой undefined.
- Validation выбирает, test оценивается один раз; cold start — отдельный holdout фирм.
- Все модели на одних строках; две популяции; интервалы — bootstrap по фирмам.
- Отрицательные результаты остаются в отчёте и в findings.
