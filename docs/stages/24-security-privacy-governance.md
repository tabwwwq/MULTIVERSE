## 1. Scope

Проверка и исправление безопасности приложения, данных и лицензий. Тесты шли только против собственного API на `127.0.0.1`. Внешние системы не атаковались. Страницы условий источников только читались.

**Что здесь не утверждается.** Реестр лицензий и инвентаризация данных — инженерный обзор, а не юридическое заключение. Отсутствие находок не доказывает отсутствие уязвимостей.

## 3. Отчёт этапа

### Done

- **Граница API (ADR-0032).** Режим `local` работает только на loopback, режим `token` требует Bearer-токен с ролью и сроком. Настройки не дают запустить `local` в production и вне loopback.
- **`Guard`** отказывает чужому `Host`, межсайтовой записи, телу не в JSON и телу больше 256 КБ. До этапа любая страница в браузере владельца могла создать и одобрить задание.
- **Владение объектами.** Задание принадлежит тому, кто его подал. Чужое отвечает 404, как несуществующее. Ключ идемпотентности привязан к владельцу.
- **Одобрение** только у `admin` и под именем из токена.
- **Лимиты вычислений.** `cloud_spend_limit_usd` впервые применяется: при подаче, при одобрении и когда воркер берёт задание. Плюс лимит активных заданий и секунд за сутки.
- **Throttling.** Минутные окна на чтение, запись и ошибки входа, ответ 429 с `Retry-After`.
- **Аудит** каждого защищённого чтения и действия, без IP и токена, 90 дней.
- **Экспорт и удаление** данных аккаунта: `GET /me/export`, `POST /me/erase`.
- **Файлы.** `protocol_path` принимает только протоколы репозитория. Вредоносный чекпоинт и кадр не выполняются.
- **Веб.** CSP и другие заголовки, CSV без формул, Markdown без разметки, лимит импорта, уведомление FRED и ссылка на условия.
- **Цепочка поставки.** Actions по полным SHA, job `Dependency audit`, ruff `S`, setuptools 84.2.1.
- **Резервные копии** с проверкой на настоящей очереди.
- **Лицензии.** Каталог получил `blocks`, новое обучение на сериях FRED отказывает, блоки показаны в Data Catalog и на `/models`.
- **Документы:** `docs/security/` и `docs/governance/`.

### Known limitations

- **LIC-001, LIC-002, LIC-003 открыты.** Модели Stages 15–17 и архив FRED нарушают текущие условия. Код лишь не даёт сделать хуже. Ничего не удалено и не переобучено.
- **Производные значения FRED уже в публичной истории.** Удаление из текущей версии их оттуда не уберёт.
- **Это не юридическое заключение.** Формулировки условий прочитаны инженером. Когда пункты FRED появились, неизвестно.
- **Статические проверки ограничены.** Пентеста третьей стороной не было.
- **Режим `token` проверен только тестами.** Настоящего развёртывания и TLS нет. Веб-страницы умеют только `local`.
- **В `local` режиме доверена вся локальная учётная запись.**
- **CSP разрешает inline-скрипты** (SEC-015).
- **Лимитер в памяти процесса,** аудит не защищён от владельца файла.
- **Бэкап на том же диске, не зашифрован, без расписания.**
- **Сканирование персональных данных эвристическое.**
- **Ветка `main` без защиты.** Настройки GitHub меняет только владелец.
- **Мутации разовые,** в CI их нет.

### Decisions

- **ADR-0032:** граница API, лимиты в очереди, блок лицензии в каталоге.
- **OQ-21 открыт:** что делать с FRED. Решает владелец.
- **Подписанные ссылки не написаны:** хранилища со ссылками нет. Правило записано.
- **Защита FRED сделана отказом, а не настройкой:** снять блок можно только решением в каталоге.
